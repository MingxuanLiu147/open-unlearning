## 1. 背景与目标

本次集成目标是：
- 在不改动现有 `src/train.py` / `src/eval.py` 文本主链路的前提下，新增一条多模态 sidecar 跑道。
- 复用上游 `code/MMUnlearner` 的核心方法思想（GA / GradDiff / KL_Min / NPO / MMUnlearner + SFRon）。
- 先在 MLLMU-Bench 跑通最小训练闭环，再逐步扩展 CLEAR 与更完整评估。

本次改动的设计目的：
- **隔离风险**：不影响原有文本遗忘流程。
- **快速落地**：优先把可运行入口和核心算法接起来。
- **便于扩展**：每个方法独立文件，后续改某个算法不会影响其他方法。

## 4. 本次关键修复记录

本次为了让最小命令可跑，做了以下关键修复：

1. **模型适配策略调整**
   - 原先固定 `Qwen2VLForConditionalGeneration`。
   - 调整为 `AutoModelForImageTextToText`，原因：本地可用的最小完整 VL 权重是 `Qwen3-VL-4B-Instruct`，其架构类不同。

2. **数据结构适配修复**
   - 原先 `MLLMUDataset` 只读 `metadata`。
   - 实际 `forget_10` parquet 为 `question/answer` 直列，已在 `src/data/multimodal.py` 兼容两种格式。

3. **优化器导入兼容修复**
   - `transformers.AdamW` 在当前版本不可用。
   - 改为 `torch.optim.AdamW`。

4. **显存优化尝试**
   - 在 `mm_base.py` 增加 `gradient_checkpointing_enable()`。
   - 目的：降低激活显存占用，提升 24G 卡上的可训练概率。

## 5. 下一步如何构建（推荐执行顺序）

### Step 1：先跑通“最小可训练”配置（必须）

建议先用以下策略降显存：
- `batch_size=1`
- `gradient_accumulation_steps=8`
- `num_epochs=1`
- 保持 LoRA，避免全参训练

推荐命令：
```bash
CUDA_VISIBLE_DEVICES=8 HF_HUB_OFFLINE=1 .venv/bin/python src/mm_train.py \
  model=Qwen3-VL-4B \
  data=mllmu \
  data.forget_split_ratio=10 \
  data.batch_size=1 \
  trainer=MMGradAscent \
  trainer.args.gradient_accumulation_steps=8 \
  trainer.args.num_epochs=1 \
  trainer.args.lr=1e-4 \
  output_dir=saves/mm_unlearn/test_ga_f10_bs1
```

如果仍 OOM：
- 进一步降到 `gradient_accumulation_steps=16`
- 关闭不必要的并行进程
- 尽量使用空闲显存更多的卡

### Step 2：跑通评估闭环

训练成功后执行：
```bash
CUDA_VISIBLE_DEVICES=8 HF_HUB_OFFLINE=1 .venv/bin/python src/mm_eval.py \
  model.model_path=saves/mm_unlearn/test_ga_f10_bs1 \
  model.processor_path=Qwen/Qwen3-VL-4B-Instruct \
  eval=mllmu
```

### Step 3：验证其他方法

按顺序验证：
1. `MMGradDiff`
2. `MMKLMin`
3. `MMNPO`（需 `oracle_model_path`）
4. `MMUnlearner`（需先生成 mask）

### Step 4：补齐 CLEAR evaluator（Phase 5）

- 迁移 `code/MMUnlearner/CLEAR_eval.py` 的完整逻辑到 `src/evals/clear.py`。
- 在 `mm_eval.py` 中完成 CLEAR 的真实评估分发与结果落盘。
