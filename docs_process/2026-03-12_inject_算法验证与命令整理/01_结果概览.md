# 结果概览

## 本轮目标

1. 说明 `inject` 三种算法如何运行：
   - `LoRA`
   - `DoRA`
   - `AdaLoRA`
2. 对三种算法做一次真实 smoke test，而不是只做配置拼接。
3. 记录本轮为跑通 `inject` 链路所修复的兼容性问题与最终可复用命令。

## 最终结论

在本地 tiny Llama 检查点 + 本地 Alpaca 格式 JSON 数据上，三种 `inject` 算法都已完成 **1-step 真实训练** 并成功保存 PEFT adapter：

- `LoRA`：通过
  - 输出目录：`/tmp/inject_smoke_lora`
- `DoRA`：通过
  - 输出目录：`/tmp/inject_smoke_dora`
- `AdaLoRA`：通过
  - 输出目录：`/tmp/inject_smoke_adalora`

## 关键结论

- 当前仓库中，自定义 inject 数据的 Hydra 覆盖路径实测应写为：
  - `data/datasets@data.train=Custom_inject`
  - `data.train.train.Custom_train.args.data_path=/path/to/train.json`
  - `data.train.train.Custom_train.args.format_type=alpaca`
- `inject` 默认配置本轮已修复为与当前 `transformers` / `peft` 兼容。
- `AdaLoRA` 在当前环境下额外需要：
  - 推导 `total_step`
  - 兼容新的 PEFT 参数容器结构
