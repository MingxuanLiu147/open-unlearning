# 验证记录

## 验证目标

1. `LoRA` 能完成一次真实 `inject` 训练。
2. `DoRA` 能完成一次真实 `inject` 训练。
3. `AdaLoRA` 能完成一次真实 `inject` 训练。
4. 三者都能成功保存 adapter，而不是只停留在配置拼接成功。

## 验证方式

- 使用本地 tiny Llama 检查点：`/tmp/inject_smoke_model`
- 使用本地 Alpaca 格式 JSON：`/tmp/inject_smoke_alpaca.json`
- 强制 CPU：`CUDA_VISIBLE_DEVICES=''`
- 每个算法只跑 1 step：`+trainer.args.max_steps=1`
- 关闭评估：`trainer.args.do_eval=false`

## 过程中发现并处理的问题

### 问题 1：自定义数据 override 路径不是直观的 `data.train.Custom_train`

现象：

- Hydra 实际展开为 `data.train.train.Custom_train`

结论：

- 当前自定义 inject 数据 override 应写成：
  - `data.train.train.Custom_train.args.data_path=...`

### 问题 2：`base_inject.yaml` 使用了过时的 `evaluation_strategy`

现象：

- 当前环境里的 `TrainingArguments` 不接受该参数名。

处理：

- 改为 `eval_strategy`
- 默认设为 `'no'`

### 问题 3：新版 `Trainer` 传入了额外参数 `num_items_in_batch`

现象：

- 旧版 `compute_loss()` 签名会直接报错。

处理：

- `compute_loss()` 统一兼容 `**kwargs`

### 问题 4：PEFT 保存时无法序列化 Hydra `ListConfig`

现象：

- `target_modules` 写回 adapter config 时 JSON 序列化失败。

处理：

- 在 LoRA / DoRA / AdaLoRA 中统一转成普通 Python `list`

### 问题 5：AdaLoRA 需要显式 `total_step`

现象：

- 当前 `peft.AdaLoraConfig` 要求 `total_step > 0`

处理：

- 在 `AdaLoRATrainer` 内部根据 `max_steps` 或数据集长度推导总训练步数

### 问题 6：AdaLoRA 正交正则分支不兼容当前 PEFT 参数容器

现象：

- 当前实现把 `module.lora_A["default"]` 当成带 `.weight` 的模块处理，但在当前环境下它可能是 `Parameter`

处理：

- 兼容 `Parameter` 与带 `.weight` 的模块两种情况
