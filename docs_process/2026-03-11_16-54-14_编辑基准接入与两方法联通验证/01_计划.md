# 编辑基准接入计划

## 任务目标

本次工作围绕 `open-unlearning` 的知识编辑链路，完成以下事项：

1. 扩展 `src/data/editing.py`，支持本地文件默认路径、结构化数据加载与不同 benchmark 的 schema 归一化。
2. 让 `ZSRE` 与 `CounterFact` 默认走仓库内的本地规范化数据文件，而不是依赖远端 Hugging Face。
3. 新增 `ELKEN`、`UnKE`、`ConceptEdit`、`AKEW`、`LEME` 对应的数据集 adapter。
4. 更新 `src/data/__init__.py` 与 Hydra configs，保证可以通过：
   - `_register_data(EditingDataset)`
   - `_register_data(ZSREDataset)`
   - `_register_data(CounterFactDataset)`
   - `class ZSREDataset(EditingDataset)`
   这种现有模式继续注册和扩展数据集。
5. 补充中文说明文档，并把 `ZSRE`、`CounterFact` 也整理成统一格式。
6. 对现有两个编辑方法做联通验证。

## 实施策略

### 1. 数据适配层

- 保留 `EditingDataset` 作为基类。
- 在基类中补充：
  - 本地 `json/jsonl/yaml` 加载；
  - 相对仓库根目录的数据路径解析；
  - 统一的 `EditingSample` 归一化逻辑；
  - locality / portability / rephrase 字段归一化。
- 针对不同 benchmark 新增子类，避免把所有 schema 分支硬塞在同一个 `if/else` 中。

### 2. 配置与注册

- 在 `src/data/__init__.py` 中注册新增数据集类。
- 在 `configs/data/datasets/` 下补充各 benchmark 的 YAML。
- 在 `configs/experiment/edit/` 下补充可直接运行的实验配置。

### 3. 中文文档

- 在本目录记录：
  - 计划；
  - 修改内容；
  - 验证结果；
  - benchmark 中文说明。
- 文档以“原始论文/官方仓库/本仓库适配方式/注意事项”四部分组织。

### 4. 验证范围

“两个方法”当前按仓库现有的两个编辑方法配置理解为：

1. `ROME`
2. `MEMIT`

验证目标不是复现实验指标，而是确认以下链路能跑通：

1. Hydra 配置能正确实例化数据集。
2. 数据集能构造出合法 `EditRequest`。
3. `ROME` 与 `MEMIT` 至少能在一个轻量模型和本地 benchmark 样本上完成一次调用。

## 风险记录

- `ELKEN` 官方仓库当前 `test.json` 文件损坏，上游文件不可直接解析。
- `UnKE`、`ConceptEdit`、`ELKEN` 的任务形式与标准 factual editing 不完全一致，需要在适配层中做“降维映射”后才能接入当前 `EditRequest` 结构。
- 当前仓库的 `ROME/MEMIT` 实现依赖 `subject` 在 `prompt` 中可定位，因此 adapter 必须优先保证 `subject` 是 prompt 的可检索子串。
