# 编辑基准中文说明

本文档把当前接入仓库的编辑 benchmark 统一整理为同一种说明格式：

1. 基准来源
2. 原论文/官方资源
3. 本仓库中的落盘位置
4. 适配到当前 `EditRequest` 的方式
5. 注意事项

## 1. ZSRE

### 基准来源

- Zero-Shot Relation Extraction 知识编辑基准。

### 原论文 / 官方资源

- 论文来源：KnowEdit / EasyEdit 体系中的标准 factual editing 基准。
- 本仓库当前本地文件：`data/edit/zsre_test_all.json`

### 本仓库落盘位置

- `data/edit/zsre_test_all.json`

### 当前适配方式

- `prompt`：原始问题
- `subject`：原字段 `subject`
- `target_new`：原字段 `target_new`
- `target_old`：原字段 `ground_truth`
- `rephrase_prompts`：`rephrase_prompt`
- `locality_inputs`：原字段 `locality`
- `portability_inputs`：原字段 `portability`

### 注意事项

- 当前仓库只有本地规范化后的 `zsre_test_all.json`，没有单独 train split。
- 为了保证本地默认路径可用，`ZSREDataset` 默认走该文件。

## 3. ELKEN

### 基准来源

- Event-Level Knowledge Editing

### 原论文 / 官方资源

- 论文：Event-Level Knowledge Editing
- 官方仓库：`THU-KEG/Event-Level-Knowledge-Editing`

### 本仓库落盘位置

- `data/edit/elken/train.json`
- `data/edit/elken/test.json`
- `data/edit/elken/test_repaired_drop_incomplete_tail.json`

### 当前适配方式

- 原 benchmark 是“事件描述 + 多个 fact/tendency 问答”结构，不是标准单条 factual edit。
- 为接入当前 pipeline，本仓库按 question-level 展开：
  - `prompt`：`Event + Question + Options`
  - `subject`：整个事件描述
  - `target_new`：对应选项答案（如 `A/B/C`）
  - `locality_inputs`：同一事件下的 `local_qas`
  - `portability_inputs`：同一事件同一 bucket 中的其它问答

### 注意事项

- 官方 `test.json` 当前损坏，不能直接解析。
- 当前默认 test 使用 `test_repaired_drop_incomplete_tail.json`。
- 此适配是为了进入现有单条编辑链路，不等于复现论文中的完整 event-level 评测。

## 4. UnKE

### 基准来源

- Everything is Editable: Extend Knowledge Editing to Unstructured Data in Large Language Models

### 原论文 / 官方资源

- 论文：UnKE
- 官方仓库：`TrustedLLM/UnKE`
- 官方 README 指出 `data/final_data_v3.json` 是 `UnKEBench`

### 本仓库落盘位置

- `data/edit/unke/final_data_v2.json`
- `data/edit/unke/final_data_v3.json`
- `data/edit/unke/alpaca_data.json`
- `data/edit/unke/mmlu_shot.jsonl`

### 当前适配方式

- `prompt`：主问题 `question`
- `subject`：从主问题中抽取的实体；抽不出来时回退到 prompt 本身
- `target_new`：长答案 `answer`
- `rephrase_prompts`：`para_question`
- `portability_inputs`：`sub_question + sub_answer`
- `locality_inputs`：`mmlu_questions + mmlu_choices + mmlu_answer`

### 注意事项

- UnKE 本身是“非结构化知识编辑” benchmark，和单跳 factual edit 不同。
- 当前适配方案保留了主问题、子问题和外部 MMLU 检查，但仍是面向现有 pipeline 的简化映射。

## 5. ConceptEdit

### 基准来源

- Editing Conceptual Knowledge for Large Language Models

### 原论文 / 官方资源

- 论文：ConceptEdit
- 官方页面：`zjunlp.github.io/project/ConceptEdit`
- 官方数据集：`zjunlp/ConceptEdit`（Hugging Face）

### 本仓库落盘位置

- `data/edit/conceptedit/concept_data.json`
- 以及若干 `final_*_{inter,intra}.json`

### 当前适配方式

- 当前 adapter 直接使用 `concept_data.json`
- `prompt`：`The definition of {concept_name} is`
- `subject`：`concept_name`
- `target_old`：原始概念定义 `concept_def`
- `target_new`：
  - `variant=intra` -> `module_intra.replace_def`
  - `variant=inter` -> `module_inter.replace_def`
- `locality_inputs`：`locality_prompt + locality_answer`
- `rephrase_prompts`：补充一个定义查询改写问句

### 注意事项

- ConceptEdit 原论文还关心 instance-level 变化与 concept consistency。
- 当前仓库适配的是能进入现有 `EditRequest` 的最小子集。

## 6. AKEW

### 基准来源

- AKEW: Assessing Knowledge Editing in the Wild

### 原论文 / 官方资源

- 论文：EMNLP 2024 AKEW
- 官方仓库：`bobxwu/AKEW`

### 本仓库落盘位置

- `data/edit/akew/CounterFact.json`
- `data/edit/akew/MQuAKE-CF.json`
- `data/edit/akew/WikiUpdate.json`

### 当前适配方式

#### AKEW CounterFact

- 使用 `requested_rewrite` 作为主编辑项
- `rephrase_prompts`：`paraphrase_prompts`
- `portability_inputs`：`generation_prompts`

#### AKEW MQuAKE-CF

- 使用第一个 `requested_rewrite` 作为主编辑项
- `portability_inputs`：`questions -> new_answer`

#### AKEW WikiUpdate

- 直接使用 `requested_rewrite`

### 注意事项

- 原始 AKEW 更强调“野外分布”与鲁棒性，而不只是单条 factual rewrite。
- 部分原始提示没有提供 locality 的精确标准答案，因此当前适配没有强行构造伪标签。

## 7. LEME

### 基准来源

- Long-form Evaluation of Model Editing

### 原论文 / 官方资源

- 论文：Long-form evaluation of model editing
- 官方仓库：`domenicrosati/longform-evaluation-model-editing`

### 本仓库落盘位置

- `data/edit/leme/counterfact_with_coupled_entities.json`
- `data/edit/leme/zsre_mend_eval_with_coupled_entities.json`

### 当前适配方式

#### LEME CounterFact

- 主编辑项来自 `requested_rewrite`
- `rephrase_prompts`：`paraphrase_prompts`
- `portability_inputs`：`generation_prompts`

#### LEME ZSRE

- `prompt`：`src`
- `subject`：`subject`
- `target_new`：`alt`
- `target_old`：`answers`
- `rephrase_prompts`：`rephrase`
- `locality_inputs`：`loc + loc_ans`

### 注意事项

- LEME 的核心关注点是 long-form 评估。
- 当前仓库只把它映射到现有 edit pipeline 的 request 结构，尚未接入论文里的完整长文本打分流程。

## 8. 当前接入结论

从“能否进入当前知识编辑链路”的角度看：

- `ZSRE` / `CounterFact`：已经是最贴近当前 pipeline 的标准基准。
- `ELKEN` / `UnKE` / `ConceptEdit` / `AKEW` / `LEME`：已经完成数据适配与注册，但属于“对现有单条编辑接口的兼容映射”，后续若要严格对齐原论文指标，还需要继续扩展评估器与请求结构。
