# LoReFT / BREP 实施路线

## Summary
本次实现不新增顶层 `mode`，而是在现有 `inject` 体系内扩展两种方法：
- `LoReFTTrainer`
- `BREPTrainer`

同时补齐注入方法的统一产物加载接口，使训练产物都能通过“基座模型 + inject_artifact”方式被评估和复用。

## Implementation Steps
1. 在 `model` 加入统一的 `inject_artifact` 运行时加载逻辑，支持 `peft`、`loreft`、`brep`。
2. 扩展 `InjectDataset` / collator，为 ReFT 提供 prompt 边界和单位位置元信息。
3. 实现 `LoReFTTrainer`，在基座模型上构建 ReFT wrapper，并统一保存 artifact 元数据。
4. 实现 `BREPTrainer` 与 activation wrapper，支持最小可运行的 BREP 训练与保存。
5. 为两种方法补齐 Hydra 配置和 experiment 模板。
6. 调整 inject eval 配置，使其不再把 artifact 路径直接当完整模型路径。
7. 增加最小 smoke test，验证 LoRA 回归、LoReFT 入口、BREP 入口。

## Deliverables
- 代码改动：trainer/data/model/eval/config 四条链路。
- 文档记录：本目录下的 `task_plan.md`、`notes.md`、实现补充记录。
- 验证结果：训练入口和加载入口的语法检查，加上能跑的 smoke test 命令。
